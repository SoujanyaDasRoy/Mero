# Mero v1 — Product Requirements Document

**Date:** 2026-09-04
**Status:** Draft for review
**Platform:** Android only (minSdk 28 / Android 9, targetSdk 36)
**Audience:** 5–10 friends, private distribution
**License:** GPL-3.0 — forced by vendoring the `innertube` module from
`z-huang/InnerTune`, which is GPL-3.0. Compatible with the non-commercial,
open-source intent, but binding: Mero must ship a GPL-3.0 `LICENSE` and
preserve upstream copyright notices.

---

## 1. Product summary

Mero is a free, ad-free music player for Android. It streams audio from YouTube
Music using an anonymous extraction library, imports existing playlists from
Spotify and YouTube, plays offline, and offers a real DSP suite (multiband EQ,
loudness normalization, crossfade).

It is built for a group of friends who all already have music libraries scattered
across services and no interest in paying three subscriptions. Feature requests
come directly from those friends and ship quickly — that responsiveness is the
product's actual differentiator, not any single feature.

### Why not just fork an existing app

Metrolist, InnerTune, SimpMusic and RiMusic already do the core job. Mero forks
the *extraction layer* from that ecosystem (`innertube`, vendored as a git
subtree) and owns everything above it. The point is a UI and feature set shaped
by ten specific people, with a turnaround measured in days.

### Legal position

Streaming audio through the InnerTube API violates YouTube's Terms of Service.
It is not DRM circumvention, and at ten private users it is not a realistic
enforcement target — but it is a ToS violation and the project should not
pretend otherwise. Mero is non-commercial, serves no ads, and is distributed
privately. Spotify's audio is Widevine-protected and Mero **does not touch it**;
Spotify is used strictly as a metadata and playlist source through the official
Web API.

## 2. Goals and non-goals

### Goals

| # | Goal | Measure |
|---|---|---|
| G1 | Play any song a friend can name, free, no ads | Search → audio out in < 3s on a mid-range device |
| G2 | Work without a data connection | Downloaded tracks play in airplane mode |
| G3 | Bring existing libraries along | ≥ 90% of a typical playlist resolves correctly on import |
| G4 | Sound noticeably better than the app they left | Multiband EQ, normalization, crossfade, gapless |
| G5 | Ship a requested feature within days | GitHub Release → auto-update on their phone |

### Non-goals for v1

Explicitly out of scope. Each is a real feature that someone will ask for; the
answer for v1 is no.

- **No account or login of any kind** — see §3.1
- No sync between friends' devices, no shared playlists, no friend feed
- No listening party / synced playback
- No SoundCloud, Bandcamp, or any second source (no source-abstraction layer)
- No iOS, no tablet-specific layout, no Wear OS
- No video playback — audio only
- No podcasts, no audiobooks
- No home-screen widget
- No lyrics editing or upload

## 3. Key product decisions

### 3.1 No Google sign-in

Mero makes anonymous InnerTube requests only. It never authenticates to a Google
account.

**Why:** signing in moves the failure mode from "an IP got rate-limited" to "my
friend's actual Google account got flagged." That is not an acceptable risk to
hand to ten people who trust you.

**Cost of this decision:**
- No personalized YouTube recommendations
- No syncing their existing YouTube Music library or likes
- Home screen must be built from local listening history plus anonymous charts
  and moods, rather than a personalized feed

This is a deliberate trade and should not be quietly reversed later.

### 3.2 Extraction happens on-device

Every phone hits YouTube from its own residential IP. There is no server.
Beyond costing nothing to run, this matters technically: YouTube blocks
datacenter IP ranges aggressively with "Sign in to confirm you're not a bot,"
so a shared VPS proxying ten users would be blocked far faster than ten phones
on mobile data.

### 3.3 Aggressive OEM battery management is a first-class problem

Xiaomi, Oppo, Vivo, Realme and OnePlus kill background services aggressively
regardless of foreground-service status. On the phones this group actually owns,
this will be the most common "Mero is broken" report — playback stops when the
screen is off.

**Requirement:** first-run flow detects the OEM and walks the user through
disabling battery optimization for Mero, with vendor-specific instructions
(Xiaomi's "Autostart" and "No restrictions" are separate settings from stock
Android's battery optimization toggle). This is a v1 requirement, not polish.

### 3.4 Manual override beats a cleverer matching algorithm

Playlist import will mis-resolve live versions, remixes, sped-up edits and
covers. No scoring function fixes this completely. v1 ships a review screen and
a manual override rather than pretending the matcher is perfect.

## 4. Feature specification

### 4.1 Search and playback — P0

- Search YouTube Music for songs, albums, artists, playlists
- Search history, stored locally, individually deletable
- Play a song immediately from any result
- **Queue:** play next, add to queue, reorder by drag, remove, clear
- **Now Playing:** artwork, scrubbable seek bar, previous/next, shuffle,
  repeat (off / all / one)
- **Mini-player** persistent above the bottom nav, expands to Now Playing
- Background playback with notification and lock-screen controls
- Bluetooth, wired headset, and Android Auto controls (free via `MediaSession`)
- Autoplay radio when the queue runs dry
- Sleep timer (15/30/45/60 min, end of track, custom)
- Playback speed and pitch control

**Acceptance:** search a song, tap it, audio starts in under 3 seconds. Lock the
phone; playback continues and notification controls work. Unplug headphones;
playback pauses.

### 4.2 Library — P0

Local only. Nothing leaves the device.

- Liked songs
- User playlists: create, rename, delete, reorder tracks, add/remove
- Recently played
- Most played
- Downloads
- Saved albums and artists

**Playlist export/import as JSON** — since there is no server, this is the
sharing mechanism. Export writes a file, share via any app; import reads it back
and dedupes on `videoId`.

### 4.3 Offline downloads — P0

- Download a single song, a full playlist, or an album
- Download queue with per-item progress and cancel
- Wi-Fi-only toggle (default on)
- Storage usage view; clear downloads and clear cache separately
- Downloaded tracks are visually marked throughout the app
- Full playback, search and browse of downloaded content with no connection

**Technical requirement:** the Media3 `CacheKeyFactory` must key on `videoId`,
not URL. YouTube stream URLs expire in roughly six hours; default URI-based
cache keys would miss on every re-resolution and silently re-download
everything.

**Acceptance:** download a playlist, enable airplane mode, play it end to end.

### 4.4 Playlist import — P0

**Spotify**

1. OAuth via PKCE — no client secret in the APK
2. List the user's playlists and saved albums
3. User selects what to import
4. Resolver matches each track to a YouTube video; progress shown per track
5. Review screen surfaces low-confidence matches for manual correction

Resolver scoring, strongest signal first:
- `|Δduration|` — under 3 seconds is near-certain
- Normalized title similarity — strip `(Official Video)`, `feat.`, bracketed suffixes
- Artist name match
- Prefer YT Music **song** results over **video** results (cleaner masters)

Results cached in `SpotifyResolution` so re-imports are instant. Manual
overrides are sticky and never re-resolved.

> **Operational note:** Spotify apps registered after November 2024 start in
> development mode — capped at 25 users, and every friend's Spotify account
> email must be added by hand in the Spotify developer dashboard. Fine for ten
> people, but it is manual setup and it is not obvious.

**YouTube / YouTube Music**

Paste a public playlist URL. `browseId` → track list, `videoId`s are native, no
resolution step. Deliberately no YouTube auth (§3.1).

**Acceptance:** import a 50-track Spotify playlist; at least 45 resolve
correctly without intervention; the rest are correctable in the review screen.

### 4.5 Audio and DSP — P0

This is G4, the reason a friend would switch.

| Feature | Implementation |
|---|---|
| 10-band equalizer + preamp | `DynamicsProcessing` (API 28+) |
| EQ presets | Flat, Bass Boost, Vocal, Rock, Electronic, Custom |
| Compressor / limiter | `DynamicsProcessing` |
| Loudness normalization | `LoudnessEnhancer`, per-track gain |
| Crossfade, 0–12s | Two `ExoPlayer` instances + volume ramp |
| Gapless playback | Native to ExoPlayer |
| Skip silence | `setSkipSilenceEnabled(true)` |
| Speed / pitch | `PlaybackParameters` |
| Battery-efficient playback | `AudioOffloadPreferences` |

Crossfade is the only genuinely custom audio code in v1; everything else is
platform or ExoPlayer configuration.

**Acceptance:** EQ changes are audible immediately without playback interruption
and persist across app restarts.

### 4.6 Lyrics — P1

- Fetch synced lyrics from LRCLIB (free, no auth)
- Synced highlight; tap a line to seek
- Plain-text fallback when no synced version exists
- Manual search override when the auto-match is wrong
- Cached locally

### 4.7 Scrobbling — P1

ListenBrainz, using a simple user token. Chosen over Last.fm because the auth
flow is a pasted token rather than a full OAuth handshake. Optional and off by
default.

### 4.8 Settings and appearance — P0

- Theme: light / dark / system, Material You dynamic color, pure-black AMOLED
- Audio quality, selected separately for streaming and for downloads:
  High (Opus ~160 kbps, itag 251) · Medium (~70 kbps, itag 250) ·
  Low (~50 kbps, itag 249). 256 kbps AAC requires a Premium account and is
  unreachable by design (§3.1)
- Download location, Wi-Fi-only toggle
- Clear cache / clear downloads
- Battery optimization helper (§3.3)
- About, version, link to the repo

## 6. Architecture summary

Full detail lives in the architecture discussion; this is the shape.

```
mero/
├── innertube/   ← git subtree from z-huang/InnerTune. Never edited.
└── app/         ← everything else, packaged by feature
```

Two modules. Multi-module Gradle buys build parallelism and team boundaries;
this is one developer and one app, so package-by-feature inside `:app` gets the
same clarity with no build-config tax.

**Stack:** Kotlin 2.x · Compose + Material 3 · Media3 (ExoPlayer + session) ·
Room + KSP · Ktor (already used by `innertube` — no second HTTP stack) · Coil 3 ·
DataStore · Koin

**Playback:** `MediaSessionService`; Compose binds through `MediaController`.

**Stream URLs are never persisted.** Store `videoId`; resolve at open time via
`ResolvingDataSource.Resolver`, which also handles re-resolution when a URL
expires mid-playback.

**Data model** (Room, natural keys — `videoId`, `browseId`):
`Song` · `Album` · `Artist` · `Playlist` · `PlaylistSongMap(position)` ·
`SpotifyResolution(spotifyTrackId PK, videoId, confidence, manualOverride)` ·
`LyricsCache` · `SearchHistory`

No download-state entity — Media3's `DownloadIndex` already is one.

## 8. Distribution

**GitHub Releases + Obtainium.** Friends install Obtainium once, point it at the
repo, and receive every subsequent release automatically.

This is not an afterthought — it is the delivery half of G5. Without it, every
feature request ends in manually sending an APK over WhatsApp, and the
responsiveness that justifies building Mero instead of forking one dies on
distribution friction.

Signed release builds, R8 enabled, one APK per release.

## 9. Risks

| Risk | Severity | Mitigation |
|---|---|---|
| PO token / extraction breakage | High | `git subtree pull` from upstream; surface a visible "extraction failed, retry" rather than a silent hang. Deferred escape hatch: `youtubedl-android` self-updates yt-dlp at runtime, fixing breakage without shipping an APK (+30 MB) |
| OEM task-killers stopping playback | High | §3.3 first-run helper |
| Spotify dev-mode 25-user cap | Medium | Manual allowlist; documented in setup notes |
| Import mis-resolution | Medium | Review screen and sticky manual override |
| YouTube rate-limiting a heavy user | Low | On-device extraction spreads load across residential IPs |
| Repository takedown | Low | Private-scale, non-commercial; precedent well established in this FOSS category |

---

## 10. Success criteria for v1

- A friend installs via Obtainium, searches, and plays a song within 60 seconds
  of first launch
- Cold start to audio output under 3 seconds on a mid-range device
- Playback survives 8 hours screen-off on a Xiaomi or Oppo device after the
  battery helper has run
- A typical 50-track pop playlist imports with ≥ 90% correct resolution
- One week of normal group use with no crashes

---

## 11. Testing

Ordinary glue code does not get tests. The resolver scoring function is the only
non-trivial logic in v1 and gets a real unit test with fixture cases covering
exact matches, live versions, remixes, and duration outliers.

Everything else is verified by using the app.
